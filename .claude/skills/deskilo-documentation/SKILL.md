# Documentation and help (DesKilo)

Binding rules: AGENT_RULES "Help symbols live in BOTH places" and "Guides &
illustrations". The portable method is `docs/guides/help-framework.md`.

**Essentials**
1. One id `<guide>.<module>.<screen>.<object>` (dotted, lower case, never translated) names four things.
2. `docs/wiki/` is the source; `assets/help/` is GENERATED by `dart run tool/build_help.dart` — commit it, never hand-edit it.
3. Five languages, structurally parallel: same headings, anchors and image names.
4. Words come from the app (ARB, registries, migrations), never from memory or a screenshot.
5. Screenshots: Demo workspace, no personal data, in the language of the guide they illustrate. The user guide and the setup guide are chapters (`docs/guide/*`, `docs/guide/AUTHORING.md`) with a re-runnable capture (`tool/guide_shots/capture.mjs`); other families use `tool/media.dart`.

Stitching incidents and the screenshot backlog: [reference.md](reference.md).

## The anchor is one identity for four things
| the id names | where it lives |
|---|---|
| a help symbol | `HelpDot(l10n?.helpTopicDeployment ?? 'Deploying', anchor: HelpAnchor.envDeployScreen)` — constants in `lib/core/help/help_anchors.dart` |
| a documented object | `<!-- anchor: env.deploy.screen -->` on the line above its heading, in all five guides of the family |
| its screenshot | `docs/wiki/images/env-deploy-screen.jpg` |
| an *Ausschnitt* of one part | `env-deploy-screen--<part>.jpg` |

Dots become dashes for a file name; `-full` marks a stitched whole form. An
invisible comment, never a visible `{#id}`: `build_help` lifts the comments into an
anchor → heading map, so the symbol opens that exact heading.

## The guides
Families `user` (en `User-Guide.md`, fr `Guide-utilisateur.md`, de `Benutzerhandbuch.md`,
es `Guia-de-usuario.md`, it `Guida-utente.md`), `config` (`Admin-Configuration-Guide{,.fr,.de,.es,.it}.md`),
`admin` (`Admin-Technical-Guide…`), `env` (`Environments-Guide…`), plus
`Technical-Reference`, `Architecture`, `Implementation`, `Home` and `_Sidebar`.

## Writing a guide section (what every /doc-* command does)
1. **Facts from the app.** For the module: its screens under
   `lib/features/<module>/presentation`, its ARB fragments
   (`lib/l10n/_fragments/*_en.arb` — every label verbatim, and the four translations
   for the other guides), its registries (`workspace_feature.dart`,
   `workspace_permission.dart`, the placeholder list, the validation domains), and the
   migrations that define what the server allows. A guide never invents a label or a rule.
2. **One anchor per documented object** (field, action, group): the comment above a
   heading named exactly as the screen names it. Add the constant to `HelpAnchor`
   (and `HelpAnchor.all`) and point the screen's `HelpDot`/`HelpDotTitle` at it in the
   same PR. A symbol needs BOTH an anchor into a family all five languages have
   (`help_anchor_test`, `help_coverage_test`) AND a localized topic needle that is a
   substring of a heading line in all five (`help_hint_test`). A shared helper that
   embeds one symbol takes an `anchor` parameter per call site — never a copy.
3. **Write it**: what the object is (one sentence), what it decides, what happens if
   left alone (the default), the rule that is easy to get wrong. Consequences, not
   mechanisms. Labels exactly as the app shows them in that guide's language.
4. **Images**: an existing image is `<p><img src="images/<id>.jpg" width="240"></p>`
   (`build_help` rewrites it to `![](assets/help/images/…)`), one topic-sized image
   beside its paragraph. A missing one is a slot, `<!-- image: <id> -->`, which renders
   as nothing — `dart run tool/media.dart slots` lists the waiting ones, `/doc-shots`
   fills them without touching a sentence. Never an `<img>` to a file that does not
   exist (`help_screen_test`). Whole-form stitches live inside `<details>`, which
   `build_help` strips.
5. **Five languages**, prose translated, structure identical; a parameter with a help
   symbol in the app carries one in `web/setup.html` too, linking `wiki/User-Guide#<anchor>`.
6. **Check** (below), then one PR per module; body: the module, the new anchors, the
   image slots still empty. Mirror the wiki with `/doc-wiki` after the merge.

Help-card hosts (`HelpHint`, Get started) are an inventory that only shrinks
(`help_host_inventory_test`, #2091): do not mount a help card from a new file.

## The screenshot pipeline — `tool/media.dart`
```
docs/media/source/    git — the originals, dated: <date>--<screen>--<n>.jpg
docs/wiki/images/     git — what the guides link (the tool's only output)
assets/help/images/   git — copied by build_help, never by hand
.media-workbench/     NOT in git — index.md + index.json: what each image shows
```
`ingest` · `merge` (`--trim-top/--trim-bottom`, `--overlap N` to force an ambiguous
match) · `crop` (`--rect x,y,w,h`, `--callout n@x,y`) · `frame` · `redact` · `describe`
· `index` · `check` · `slots`. Run `dart run tool/media.dart` for the usage.

- **Replacing an image renames nothing**: ingest a new capture under the same screen
  id and the same `docs/wiki/images/<screen>.jpg` is overwritten; every link in every
  language keeps working.
- **Stitching**: measure the trims per batch (status bar + dev banner + app bar —
  390 px on the reference device, navigation bar 120), never a constant; trust the
  render, not the score (crop each junction and LOOK); a junction with nothing in
  common is butt-joined, not invented. Stage originals under zero-padded names in
  scroll order. The algorithm itself: user-level `screenshot-doc-pipeline`.
- **Shoot in the guide's language.** The user and setup guides carry one image per language,
  named `<id>.<lang>.b<commit>.jpg`, produced by `tool/guide_shots` from a built web app (see
  `docs/guide/AUTHORING.md`); the other families keep one English image set (#1198).
- **Shoot in the Demo workspace.** `docs/media/source/` is in git and images ship in
  every store build, so `ingest` of a real workspace is already too late (the data
  enters history). Hand redaction misses things (#1514). Ask before ingesting: re-shoot
  in Demo, or redact first and check band by band. The render-tree blur is forbidden
  (`no_render_tree_blur_test`) — it failed open.

## Before pushing
```
dart run tool/media.dart check       # images ↔ references
dart run tool/build_help.dart        # regenerate the in-app copy, commit assets/help
flutter test test/lint test/features/help test/core/help
```
For non-ASCII edits through a python heredoc, run with `PYTHONUTF8=1`.
