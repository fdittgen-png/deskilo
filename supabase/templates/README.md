# Builtin workspace templates

One JSON file per builtin, named by its key. This is the reviewable source;
the migration that inserts or updates the builtin carries the same payload.
`test/lint/template_contract_test.dart` holds both to one contract (#1282):

- the file and the migration agree (a drift gate: a builtin edited in one
  place only fails);
- every builtin passes the contract: key shape, feature profile consistent
  with `featureManifest` (a child never on without its parent), working
  hours in order, known granularity and weekdays, non-negative prices, fee
  bands that neither overlap nor strand an offered subscription level, VAT
  labels that exist, lexicon overrides that keep their placeholders, entities
  that exist, and nothing from the publication deny-list.

## Owner-private variants (`variants/`)

A variant is a template prepared for ONE space. It is not a builtin: no
migration inserts it, nobody else may read it, and it reaches its
workspace through the ordinary publication flow. The contract test above
does not see these files — `test/lint/pezenas_template_test.dart` holds
each variant to the same `checkTemplate` and to two more things:

- a `provenance` block, one row per decision, saying whether the value
  was `explicit` (the source document asked for it), a `correction` (it
  asked for something that cannot be taken literally), `unresolved` (it
  did not give enough to decide) or `inherited` (nobody asked; a default
  answered). `<key>.md` beside it is that block, rendered, and is
  regenerated by the same generator;
- an `acceptance` table, held equal to the pgTAP file that proves it
  against the actually-applied payload.

`provenance` and `acceptance` describe the payload and are not part of
it: only `configuration` and `floor_plan` are ever written to a
workspace.

A template may carry `configuration.holidays = {"years": 2, "country"?: "FR"}`
instead of dated closure days: it is resolved per target workspace at preview
and apply time (0234), for the target's country unless one is named, skipping
invoiced months. Feature flags are written as `feature_profile` and expanded
by `dart run tool/build_builtin_templates.dart`.

Shape:

```json
{
  "key": "tiny", "name": "…", "description": "…", "sort_order": 0,
  "visibility": "builtin", "schema_version": 1, "tags": [],
  "entities": ["floor_plan"],
  "configuration": {"workspace": {}, "tables": {}},
  "floor_plan": []
}
```
