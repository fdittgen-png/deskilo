## Executive summary

**No cross-tenant read or write was found.** RLS is on for 206 of the 207 public tables (the 207th has no client grants). Every anonymous read probe was refused or returned nothing. No definer function can be executed by `anon`, every definer function pins its `search_path`, and the 70 client-callable definer functions with no obvious check all establish the caller and tie each row back to its workspace. The exceptions are six low-severity cases: five existence/state oracles and one cross-tenant id reference. No secret is committed, in the current tree or in history.

The confirmed findings are on the edges:
- an admin-reachable SSRF in the generic e-invoice connector (Medium)
- the badge sign-in's brute-force and enumeration margins (Medium)
- an unauthenticated push trigger (Low-Medium)
- CI supply-chain pinning (Medium)

Each has a bounded remediation issue:

## Method notes
- The anon probe is reproducible. Inside `begin … rollback`: `set local role anon`, then `count(*)` per granted table, catching each error. A 42501 means a policy helper's EXECUTE is revoked from anon, so the denial is real but takes the form of an error rather than an empty set. SEC-D1 makes it an empty set by grant.
- The 70-function read used the live bodies from the dev catalog and the latest migration defining each helper. The functions that take a workspace id never load a row by its own id without tying it back to that workspace.
- Edge findings cite file:line at the audit commit; see the issues for the fixes and tests.

## What changes in the threat model
T4 ("3 definer functions answer for any workspace", #1228) no longer holds. No function answers for a foreign workspace; six Low items remain (#3095). T10/T11 are evidenced in CI (`deno test`, `20_money_invariants`). New threats: T17 (SSRF through an admin-configured endpoint, #3090), T18 (credential brute force on the kiosk, #3091), T19 (CI supply chain, #3094).
