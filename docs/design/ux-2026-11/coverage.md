## How to read the columns

- **Who may open**: route class (RouteClass), the permission list of routePermissions (holding ANY opens), the WorkspaceFeature the route is guarded by, and what the router does for a member, an admin and an owner with every feature on (route_outcomes.golden: "open" or the redirect target). The golden is a router outcome, not a rendering.
- **Desk guard**: window sizes at which test/ux/desk_guard_pages_test.dart runs deskGuardProblems + keyboardProblems on the page (768x1024, 1024x768, 1440x900, 1920x1080); `768` is absent where the test lists the page in `_waitsAt768`. Sheets are pictures, not checks. Sheets are written at 390 and 1440. The owner is guarded at the four desk sizes only; a member and an administrator are guarded (#4076) at 1440 (the desk guards) and 390 (the phone guard: no overflow, no cut title, targets of 48 dp, controls named) on every page the router opens for them (the `_personaFindings` list of that file holds what is left out, with its measurement).
- **Phone guard**: other tests that guard a phone width on the route (pocket, Me, information-cut, invoicing).
- **a11y matrix row**: row of test/a11y/matrix.dart that pumps this route; axes: narrow 360 + 320 dp, wide 1200, 2.0x text, Tab traversal, WCAG guidelines (48 dp, labels, contrast), reduced motion, dark, and four other languages at phone width. "no" = no row.
- **Tab walk**: keyboardProblems in the desk guard page, or the matrix keyboard axis.
- **Demo scenario**: demo_scenarios_test.dart keeps one entry per WorkspaceFeature; an entry is a CHECK OF SEEDED STATE or a precondition of an action against the Demo fixture (kind state/action/toggle, persona), it does NOT render the route. "Demo test" lists test files under test/core/demo or test/ux/demo_* that name the route or its screen class (name match).
- **States with a test**: test files that name the route or its screen class (search by path literal or class name, class names used by more than two routes ignored) and have a test whose NAME mentions the state (load, empty, fail/error/retry, refused/denied/redirect, unsaved/discard). Name-matched, not verified one by one; "none found" means no such name was found, not that the state is certainly untested. The only declared state model is test/ux/state_model_test.dart, which asserts eight states on four surfaces (new-member defaults, managed identity read, availability freshness, booking-window gate).
- **Personas rendered**: desk guard pages are pumped with FakeWorkspaceRepository.withWorkspace whose default member is isOwner:true (lib/core/demo/data/fake_workspace_state.dart:44) and all features on, with synthetic fixtures (not the Demo seeds). Since #4076 the same pages are also pumped as an administrator and as a plain member (the router golden's identities); test/ux/page_states_test.dart renders the empty, failed and refused states of the members, documents, purchases and invoices pages. "member/admin evidence by name" = a test file naming the route/class that also sets DemoPersona.member/admin or isOwner:false.
